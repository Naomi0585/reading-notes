## Bash Command Line Tutorials 

After working through the Bash command line tutorials, I gained a better understanding of how the terminal works and why it is such an important tool for software development.The command line is a text-based way of communicating directly with the computer by entering commands and receiving output. I also learned that Bash is the shell responsible for interpreting many of those commands. One thing that stood out to me was that commands can include options and arguments, which allow the same command to behave in different ways. I also found the command history useful because using the up and down arrow keys makes it easier to reuse commands without typing them again.

The **navigation section** helped me better understand how Linux organizes files and directories. Commands such as pwd, ls, and cd are basic but extremely important. Some commands I practiced on this section were:
```
pwd
ls
ls -l
cd Documents
cd ..
cd ~
```

* One of my biggest “ah hah” moments was understanding why commands sometimes fail when I am in the wrong directory. Previously, I sometimes focused only on whether the command itself was correct.

The section about **Files** helped me understand that Linux treats files differently than systems such as Windows. I also learned the importance of case sensitivity in this section. Some of the most useful commands were:
```
mkdir
touch
cp
mv
rm
rmdir
```

On the **Manual Pages** section for me was one of the most useful parts of the tutorial because programming involves constantly learning new commands and tools. Instead of relying completely on memory, I can use documentation to figure out how a command works. I also experimented with options such as:

```
ls -a
ls -l
ls -alh
```

This helped me understand how several short options can sometimes be combined into one command.

The **cheat sheet** was helpful because it brought the major commands together into one reference.One of my biggest takeaways from these lessons is that the command line becomes much easier when I think of commands as small tools that can be combined instead of trying to memorize everything at once. The concepts that stood out most were understanding relative versus absolute paths, recognizing that Linux is case sensitive, using manual pages instead of trying to memorize every command, and realizing how much control commands such as `mv`, `cp`, and `rm` provide. These fundamentals will make it easier for me to work with Git, Node, project directories, servers, and other development tools as I continue learning software development.
